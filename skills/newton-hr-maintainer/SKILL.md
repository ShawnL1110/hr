# Newton HR 接手规约

目标：HR 团队独立改进 HR 功能，保持 stuff 的催收、客服、回款统计与现有业务持续运行。

首次接手先读 [项目状态与入口](references/project.md) 和 HR 仓库 `docs/implementation.md`。部署或配置前读 [部署与隔离](references/operations.md)；改登录、角色或数据接口前读 [接口与数据边界](references/boundaries.md)；获取凭据读 [权限与密钥](references/access.md)。这些资料随 skill 一起交付，无需拥有原维护人的本地 skill。

## 可以独立开展的工作

- 在 `git@github.com:ShawnL1110/hr.git` 开发 HR 页面、员工档案、合同、招聘、请假、经审批的考勤、薪酬规则及计算功能，增加对应测试和迁移。
- 修改 `hr/` 的独立实现；HR 权限、配置和业务数据由 HR 服务管理。
- 在本地/测试环境开发并提交 PR。拿到仓库权限不等于拿到生产发布权限；按已授予的 HR 发布流程上线。
- 技术优化保持现有已确认工资、签署证据和有效日期口径。需要改变工资计算方式时，先明确业务规则、适用日期及历史数据处理，再实现。

## 不能跨越的边界

- 不改 stuff 的催收/客服/WA/电话、案件分配、回款事实或已上线统计；不部署、重启或迁移 stuff、finance、KYC、Caddy 等其他服务。
- `integrations/stuff/` 是提供端参考代码，改文件不会自动更新 stuff。登录或业务接口需求交给 stuff 维护方评审、实现、发布；不能直接把它复制上线。
- 不挂载或写入 stuff 数据库、备份、会话库及附件卷；不复制客户数据或整份生产凭据。
- 不更改共享网络、宿主端口、反向代理总配置、资源限制或取得 Docker socket/宿主 root。需要这类改动时提交具体变更给平台维护方。
- 当前是只读快照试运行，不是完整 HR 切换。迁出某模块前，必须完成数据校验、接口依赖和单一写入方切换；不能直接在两边同时开放写入。

## 每次工作

1. 查看当前 Git 状态、最新文档和实际部署版本，保留别人的未提交工作。明确本次变化是否涉及跨系统边界。
2. 在 HR 仓库实现、运行有关测试；改变工资算法时做逐项金额对账，改变合同流程时验证权限和审计证据。
3. 提交并推送已验证改动。发布使用 HR 专用权限；如果尚未配置该权限，交付具体提交、迁移和验收计划给平台维护方，不能借用其主机密钥。
4. 核对 HR 健康、登录、员工访问范围、附件访问和受影响功能；确认 stuff/finance 仍正常。报告真实结果，区分开发完成、部署完成和业务切换完成。

密钥不得进入 skill、Git、截图、日志或回答正文；通过独立私密交接包使用。skill 是工作规约，不是权限控制，也不会自行授予 GitHub 或服务器访问权。
